validation/rules:
- user can only be assigned to one room at a time
- all camp tracks/beats marked as private. they should only be accessible to users in camp.
- when a user builds on a beat, the resulting track should be marked with the user's room id
- once a track has a room_id, all descendants should be marked with the same room_id, no matter the room_id of the user who added to the track
- beat uploads allowed anytime during camp period (from creation date to end date)
- track uploads only allowed after camp has started (after start_date)
- camp user limits enforced based on product version (10, 25, 50, or 100 users)
- camp endpoints
- track upload ednpoint updates:
    - if camp_id supplied, then run camp validations
    - if parent_track_id supplied, then upload is a Track
        - ensure camp exists, is active, and user is a member of the camp
        - ensure room_id supplied and room exists
        - bypass private track check
    - if no parent_track_id supplied, then upload is a Beat
        - ensure camp exists, hasn't ended, and user is a member of the camp (can upload )
