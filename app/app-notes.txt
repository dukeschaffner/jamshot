About
This is an app/website that allows music artists to collaborate with smaller artists/fans, but in more of a social media format. for instance, an artist would upload a clip that they recorded, and people could attach audio files onto the original recording as a new version. the app would have a like/ranking system and have a featured page to show popular collabs.


Goals/VALUE
- music collaboration as a social media
- Democratize music creation
- allow musicians to make a meaningful/valuable piece of work without having to complete the process of recording a song from start to finish
- tracks around 30-90s will be prioritized in the algorithm to make it simple, fun, and pair well with short form video content like Tik Tok.
- The equivalent of going from books/publications to posts on social media. New content is released daily and from more sources, and just as social media posts allow you to comment your textual thoughts/ideas on someone else's textual posts, with this app, you can comment your musical thoughts/ideas on someone else's musical posts
- the simple DAW makes it easy to get into music recording

Features
- home feed with tracks/collabs posted by user's follows mixed with popular tracks
  - click on a track to expand and see other collabs
- users will have profiles and can be verified artists. There will be a profile page with the user's tracks, picture, reposted tracks, liked tracks, follower count, etc
- It will also work as a streaming service, were a user can pick a genre and just listen
  - tracks will have genre and instrument tags to help accommodate this
- strong interaction between artists/fans or smaller artists, as well as friend groups who want to quickly and easily share ideas. success likely determined by how many medium to large artist adopt and use the platform.


Layout
- Navbar with links to home, user account, upload, and a search bar. 
- global player with track navigation buttons (previous, play/pause, next, shuffle, loop), track title/artist username, song progress indicator


Pages
- Home
  - Contains the user's feed, generated from an algorithm
  - the tracks are shown as an expandable card containing a play button, the user's profile picture, user name, the track title, play count, like count, and a "collaborate" button
  - When the track is expanded, it shows a list of tracks containing the track that the current track is based on "original" or "based on" and all the tracks based on the current track. There will be fewer details shown on these items. play button, track title - username, like count, play count

- standard login/register pages (email, password, username)

- upload
  - allows user to upload file, name track, and upload the track

-user
  - shows user name, follower/following count, follow button, liked tracks, and all uploaded tracks (the same expandable view as the tracks in the home page)

- track/[trackId]
  - has a simple DAW that allows the user to turn on metronome/looper and drag the track and the looper range so it's all aligned. This will allow users to quickly and easily brainstorm/get inspired from a track.
  - user can either record from an audio input, recording several takes and selcting the best one, or upload audio file to attach collaboration
  - edit track
    - deleting a track is a soft delete if the track has collabs
- explore/[trackId]
  - allows users to explore entire track tree, showing the track, all of its ancestors up to the original, and all of its immediate children
  - user can select any ancestor or child track to show the track tree for that track



PRIVACY RULES

Loading:
- if a user is private, their tracks will not load in track lists unless 
    current user is authenticated and following the track owner
- if a track is private, the track will not load in track lists
- if a track is private, the track will ONLY load for other users on the track details page, 
    and ONLY if they have the secret or they have been granted access via a group.
- No restrictions on loading private tracks if the current user is the track owner

Collabs:
- any collab on a public track MUST be public.
- the privacy status of a collab on a private track (permitted by secret key) 
    is dependent on the original track. if the original track goes public, so do all of its descendents.
- all collabs on a private track should share the same secret key
- track CANNOT go from public to private if it has collabs
- as a result, collaborating artists have no control over the privacy status of their track





PostgreSQL db structure:

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL, -- Hashed with bcrypt
  profile_pic_url VARCHAR(255), -- S3 URL for profile pic
  bio TEXT, -- Optional short bio
  verified BOOL not null default false, -- Reserved for well-known artists
  email_verified BOOL not null default false, -- For email verification
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  is_private BOOLEAN NOT NULL DEFAULT FALSE,
  is_supporter BOOLEAN NOT NULL DEFAULT FALSE,
  terms_accepted BOOLEAN NOT NULL DEFAULT FALSE,
  privacy_policy_accepted BOOLEAN NOT NULL DEFAULT FALSE,
  policy_accepted_at TIMESTAMP,
  policy_accepted_ip VARCHAR(45),
  policy_version VARCHAR(10) DEFAULT '1.0'
);

CREATE TABLE tracks (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE, -- Who uploaded it
  title VARCHAR(100) NOT NULL,
  audio_url VARCHAR(1000) NOT NULL, -- S3 URL for the clip
  combined_audio_url VARCHAR(1000) NOT NULL,
  duration FLOAT NOT NULL, -- Seconds, for UI display
  layer INT NOT NULL, -- 0-4 (max 5 collaborators)
  parent_track_id INT REFERENCES tracks(id) ON DELETE SET NULL, -- Null for originals, links to parent for versions
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  play_count INT DEFAULT 0,
  is_private BOOLEAN NOT NULL DEFAULT FALSE,
  metronome_bpm INTEGER,
  metronome_offset FLOAT DEFAULT 0,
  time_signature VARCHAR(10) NOT NULL DEFAULT '4/4',
  secret_token VARCHAR(64), -- For secure sharing of private tracks
  allow_download BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE likes (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  track_id INT REFERENCES tracks(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (user_id, track_id) -- Prevent duplicate likes
);

CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  track_id INT REFERENCES tracks(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  parent_comment_id INT REFERENCES comments(id) ON DELETE CASCADE
);

CREATE TABLE featured_tracks (
  id SERIAL PRIMARY KEY,
  track_id INT UNIQUE REFERENCES tracks(id) ON DELETE CASCADE,
  featured_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  expires_at TIMESTAMP -- When it drops off the featured page
);

CREATE TABLE follows (
  id SERIAL PRIMARY KEY,
  follower_id INT REFERENCES users(id) ON DELETE CASCADE,
  following_id INT REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (follower_id, following_id) -- No duplicate follows
);

CREATE TYPE notification_type AS ENUM ('new_version', 'like', 'comment', 'featured', 'repost','follow_request');

-- Recreate the notifications table with the proper type
CREATE TABLE notifications (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  type notification_type NOT NULL,
  related_track_id INT REFERENCES tracks(id) ON DELETE CASCADE,
  is_read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  related_user_id INT REFERENCES users(id) ON DELETE CASCADE
); 

CREATE INDEX idx_notifications_user_id_created_at ON notifications(user_id, created_at DESC);
CREATE INDEX idx_notifications_user_id_is_read ON notifications(user_id, is_read);
CREATE INDEX idx_notifications_type ON notifications(type);

-- New tables for genre and instrument tagging system

CREATE TABLE genres (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE instruments (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE track_genres (
  id SERIAL PRIMARY KEY,
  track_id INT REFERENCES tracks(id) ON DELETE CASCADE,
  genre_id INT REFERENCES genres(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (track_id, genre_id) -- Prevent duplicate genre tags for a track
);

CREATE TABLE track_instruments (
  id SERIAL PRIMARY KEY,
  track_id INT REFERENCES tracks(id) ON DELETE CASCADE,
  instrument_id INT REFERENCES instruments(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (track_id, instrument_id) -- Prevent duplicate instrument tags for a track
);

-- Table for tracking plays
CREATE TABLE track_plays (
  id SERIAL PRIMARY KEY,
  track_id INT REFERENCES tracks(id) ON DELETE CASCADE,
  user_id INT REFERENCES users(id) ON DELETE SET NULL, -- Can be NULL for anonymous plays
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Create function to update play_count on tracks
CREATE OR REPLACE FUNCTION update_track_play_count()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE tracks
  SET play_count = (SELECT COUNT(*) FROM track_plays WHERE track_id = NEW.track_id)
  WHERE id = NEW.track_id;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Create trigger to update play_count when a new play is recorded
CREATE TRIGGER track_play_count_update
AFTER INSERT ON track_plays
FOR EACH ROW
EXECUTE FUNCTION update_track_play_count();

CREATE TABLE follow_requests (
  id SERIAL PRIMARY KEY,
  requester_id INT REFERENCES users(id) ON DELETE CASCADE,
  target_id INT REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (requester_id, target_id) -- Prevent duplicate requests
);

CREATE TABLE refresh_tokens (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  token VARCHAR(255) UNIQUE NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  revoked BOOLEAN DEFAULT FALSE,
  device_info TEXT -- Optional: Store device/browser info for token management
);

-- Create index for faster token lookups
CREATE INDEX idx_refresh_tokens_token ON refresh_tokens(token);

-- Create index for user's tokens
CREATE INDEX idx_refresh_tokens_user_id ON refresh_tokens(user_id);

CREATE TABLE payments (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE SET NULL,
  amount DECIMAL(10, 2) NOT NULL,
  currency VARCHAR(3) NOT NULL DEFAULT 'USD',
  stripe_payment_id VARCHAR(255) NOT NULL,
  stripe_checkout_id VARCHAR(255) NOT NULL,
  status VARCHAR(50) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Create index for user payments
CREATE INDEX idx_payments_user_id ON payments(user_id);

-- Create trigger to automatically update the updated_at timestamp when a comment is edited
CREATE OR REPLACE FUNCTION update_comment_timestamp()
RETURNS TRIGGER AS $$
BEGIN
   NEW.updated_at = NOW();
   RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_comment_timestamp
BEFORE UPDATE ON comments
FOR EACH ROW
EXECUTE FUNCTION update_comment_timestamp();
